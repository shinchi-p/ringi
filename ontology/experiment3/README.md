# ontology/experiment3

連載第3回で使った実験コードです。第2回で4対1に割れた判断を、遷移ではなく
不変条件として書いて渡したら、割れが消えるかを確かめます。

## 背景

第2回では、差戻し時に承認ステップをリセットする位置が割れました。
`Reject` の中が4回、`Submit`（再提出時）の中が1回です。

どちらも最終的な動作は同じで、違いが出るのは差戻し中の申請を表示したときだけです。
`Submit` でリセットする実装では、差戻しのあいだ承認済みの段が残ります。

## 実験の設計

第2回の table-steps のプロンプトに、制約を一行足します。

```
差戻し状態の申請は、承認済みの承認ステップを持ちません。
```

この一文は、いつリセットするかを書いていません。遷移ではなく、ありえない状態を
書いています。それでも、`Submit` でリセットする実装はこの条件を破ります。

| 条件 | 渡したもの |
|---|---|
| steps-only | `status.go` + 承認ルートの説明（第2回の table-steps と同じ。対照） |
| steps-constraint | 上記 + 制約を一行 |

各条件5回ずつ流します。

## 実行

```sh
export ANTHROPIC_API_KEY=...   # PowerShell は $env:ANTHROPIC_API_KEY = "..."
go run .
```

`out/<条件名>/` に、渡したプロンプト（`prompt.txt`）と各回の出力
（`run-01.go.txt` 〜 `run-05.go.txt`）が保存されます。

生成結果なので、同じプロンプトでも実行時期やモデルによって変わります。
再現しない場合があることを前提に読んでください。
